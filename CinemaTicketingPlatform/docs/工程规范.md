# 工程规范（Engineering Standards）

> 项目：简易电影购票平台
> 配套文档：需求纪要（Cinema_Ticketing_Platform_Design_Notes.md）、API 接口大纲、环境初始化
> 适用范围：本项目全部代码与交付物

## 1. 代码与架构

### 1.1 后端分层

- api（路由层）：只做参数接收、调用 service、返回结果；不写业务逻辑
- services（业务层）：承载全部业务规则（锁座、票状态机、转赠、退款、冲突检测）
- models（ORM 层）：SQLAlchemy 2.0 模型，与数据库表一一对应
- schemas（Pydantic）：请求校验与响应模型
- 事务边界：service 内显式管理事务；先校验后变更；防超卖使用原子 UPDATE（WHERE status=AVAILABLE 并判断影响行数）

### 1.2 前端

- React + TypeScript + Vite + Ant Design
- 页面组件化：pages（路由页）、components（可复用组件，如 SeatMap）、stores（Zustand）
- 统一 API 封装模块：所有请求走拦截器（附加 JWT、统一错误处理）
- 类型对齐：优先由后端 OpenAPI 生成 TS 类型，避免手写不一致

### 1.3 代码风格与工具

- Python：ruff（lint + format），类型注解完整
- 前端：ESLint + Prettier
- Git：Conventional Commits（feat/fix/docs/test/refactor/chore），功能粒度提交
- 可选 pre-commit：ruff、eslint、类型检查

## 2. 健壮性与异常处理

- 统一异常体系：
  - BizError：业务规则冲突（座位已被占、票数超限、转赠违规等）
  - NotFoundError：资源不存在
  - PermissionDenied：无权限
  - ValidationError：参数非法
  - 系统异常兜底转 500
- 统一响应格式：`{ "code": 0, "message": "ok", "data": ... }`，业务错误时 code 非 0
- 全局异常处理器：FastAPI exception_handler 统一输出
- 事务回滚：异常自动回滚，不留半成品数据
- 幂等：支付回调按 provider_trade_no 去重；退款审核状态机防重复处理
- 定时任务：try/except + 结构化日志 + 失败计数与下次重试
- 日志：结构化（时间、级别、请求ID、路由、耗时、用户ID），中间件生成请求ID贯穿链路
- 测试：pytest + httpx（异步），核心用例必须覆盖：
  1. 两个用户并发抢同一座位，仅一人成功
  2. 锁座 20 分钟到期自动释放
  3. 停售/支付截止到点强制释放
  4. 3 张票上限（待支付 + 待使用）
  5. 转赠仅一次；受赠票不可再转、不可退款
  6. 退款扣 10% 手续费，座位回待售（停售前）
  7. 开场前 10 分钟冻结（不可转、不可退）
  8. 排片冲突检测（同场馆 + 30 分钟缓冲）

## 3. 安全保障

- 密码：bcrypt 哈希存储，绝不存明文
- 认证：JWT（短期有效、密钥放 .env、role 权限校验）；管理员接口统一 require_admin 依赖
- CORS：白名单配置（.env），生产环境严格限定域名
- 注入：一律 ORM 参数化，禁止拼接 SQL
- XSS：React 默认转义；输入一律校验/清洗
- 限速：登录接口速率限制（slowapi），防爆破
- 密钥管理：.env 不入库不入仓，提供 .env.example；生产密钥另行设置
- 支付安全：支付宝回调验签；金额一律以数据库为准，前端金额仅展示
- 敏感操作：转赠、退款、核销均校验当前用户身份与票归属

## 4. 性能与扩展性

- 索引：外键与常用查询条件建索引，例如 sessions(venue_id, start_at)、session_seats(session_id, status)、tickets(owner_user_id, status)；唯一约束兜底（座位行列唯一等）
- 分页：列表接口统一 page/page_size 并返回 total，禁止无条件全表返回
- N+1：关联查询使用 selectinload / joinedload
- 连接池：SQLAlchemy pool_size、pool_recycle 配置（对齐 MySQL wait_timeout）
- 冗余字段：session_seats.status 直接反映可售状态，避免每次实时聚合
- 扩展点：
  - 支付：payments/ 抽象层（base/mock/alipay），新增渠道只加实现类
  - 票价：session_seats.price 预留分区/座位定价
  - 缓存：后续可加 Redis 缓存场次余票与座位图
  - 实时：先轮询，后续 WebSocket 推送座位变化

## 6. 开发流程

- 按里程碑推进：基础 → 票务状态机 → 支付/退款 → 转赠 → 管理后台 → 打磨
- 每个功能点一个提交，先测试后合入
- 阶段验收：跑通测试 + 手动流程演示
